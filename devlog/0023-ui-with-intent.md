# #23 — 画面にも、理由を持たせる

ここまでのNOA Systemは、まず「ちゃんと遊べること」を優先してきました。

ゲームを選ぶ。起動する。セーブする。続きを残す。プレイ中にメニューを開く。

必要な機能は少しずつ揃ってきましたが、画面そのものは長いあいだ開発用の姿を残していました。

それは半分、意図的です。

UIは作り始めると、あとで必ず変えたくなる。

だから先に機能と構造を作って、見た目はなるべく我慢する。

でも、そろそろ少しだけ始めてもよさそうでした。

今回はLibrary、Game Detail、プレイ中のMenuに共通するVisualと操作感を整えながら、NOA Systemが画面上でも少しずつ「何を大事にしているものなのか」を持ち始めた話です。

---

## まず、画面を作る前に空気を作る

最初に手を入れたのは、LibraryやDetailのレイアウトそのものではありませんでした。

先に共通の土台を作りました。

- dark navy / blue-grayを基調にした色
- 通常の選択を示すsoft blue
- PLAYやRESUMEのようなPrimary Actionを示すgreen / emerald
- とてもゆっくり動くgradient背景
- 入力を邪魔しない短い画面transition
- gamepad-firstの共通navigation

背景は、数秒ごとに「動いています」と主張するanimationにはしていません。

一見すると静止している。

でも、しばらく見ていると少しずつ空気が動いていることに気付く。

そういう変化を狙いました。

画面遷移も同じです。

animationを見せたいのではなく、操作した瞬間の硬さを少しだけ取り除きたい。

そのためtransition中でも入力を待たせません。

UIの演出そのものより、触ったときの気持ちよさを優先します。

---

## ゲーム棚は、少し静かになった

次にLibraryを整理しました。

以前は各ゲームの行にSystem名まで繰り返し表示していましたが、Systemはゲームごとの属性というより、今見ている棚全体の文脈として上に出すようにしました。

ゲームの行は、Titleを中心に必要な情報だけを置きます。

まだLibrary側に存在しない情報を、それっぽく推測して埋めることもしません。

Yearが無ければ `--`。

Maker / Publisherの構造化データがまだ無ければ、無理に表示しない。

空欄があることより、分からないものを分かったふりする方が嫌でした。

そしてL/RでSystemを切り替えられる導線も入りました。

今は一つのSystemしか見えなくても、これから別のゲーム機が増えていくことを前提に、Libraryそのものを作り直さなくていいようにしてあります。

小さな花のmarkも、この頃から画面に入り始めました。

まだ意味は秘密です。

---

## Detailは、デバッグ画面から「ゲームの場所」へ

Game Detailも整理しました。

開発中に便利だったstatus表示を減らし、Title、System、Year、Sizeなど、そのゲームを見るときに意味のある情報を前へ出します。

特にSizeは残しました。

数MB、数百KBという容量感も、レトロゲームを見る面白さの一部だと思っています。

右側には将来Screenshotなどを置けるMain Visualの場所を作り、まだ画像が無いときは素直に `NO IMAGE` と表示します。

背景には、Libraryの小さなmarkとは逆に、とても薄く大きな花を置きました。

同じmotifでも、画面ごとに同じ使い方はしません。

---

## 「PLAY / LAST SNAP」を、やめた

ここで、前の日記から続いていた小さな違和感が一つ形になりました。

AutoSnapを作った直後は、Game Detailで

```text
PLAY
LAST SNAP
```

のように、普通に始めるか続きを始めるかを選ばせる形も試していました。

便利です。

でも、少し使うと何かが違いました。

遊びたい人が毎回「今回はどの開始方法ですか」とエミュレーションの事情を選ぶ必要はない。

そこで通常の入口を **PLAYひとつ** に戻しました。

AutoSnapがあるかどうかはNOA System側が判断します。

```text
PLAY
  ↓
続きがあれば、続きへ
無ければ、最初から
```

機能を減らしたわけではありません。

仕組みを見せるのをやめました。

前回「便利だけど、なんか違う」と感じていたものが、早くもUIの判断へつながった最初の例になりました。

---

## メニューを開いても、ゲームの中にいる

プレイ中のMenuも見直しました。

以前のように黒い別画面へ切り替わったように見せるのではなく、ゲーム画面を残したまま、その上へ半透明のdark navyを重ねます。

```text
ゲーム画面
   +
半透明のOverlay
   +
RESUME / SAVE STATE / LOAD STATE / RESET / EXIT GAME
```

Menuを開いても、さっきまで遊んでいたゲームとのつながりを切りません。

RESUMEはGame DetailのPLAYと同じくgreen系。

SAVE STATEやRESETなどの通常項目はsoft blue。

色そのものに説明文はありません。

でも、「ゲームへ戻ること」と「何かを操作すること」が少し違う行為だと、触っているうちに感じ取れるようにしたい。

これは見た目を格好よくするためだけの変更ではありませんでした。

**その操作が今いる文脈の中で何を意味するのかを、できるだけ説明せずに伝えたい。**

そんな考え方をUIへ入れ始めています。

---

## まだ完成形ではない

もちろん、この時点のUIが完成形ではありません。

配置も色も、きっとまだ変わります。

今後情報が増えれば、`--` だった場所にも少しずつ内容が入っていくはずです。

Systemも増えます。

画像も増えます。

花の意味も、いつかもう少し見えてくるかもしれません。

それでも今回、少なくとも一つ変わったことがあります。

それまでは主にコードやデータ構造の中にあったNOA Systemの考え方が、画面の静けさや色、遷移、操作の文脈として少しだけ外へ出てきました。

機能を作るだけでなく、**どう感じてほしいかを実装する段階**が始まったのだと思います。

---

## micから

UIは実装中に作っても後で絶対に変えたくなるから、ずっと我慢してた。
でも少し取り組みたくなって、基本の仕組みだけじゃなく「UI/UXはこういうのが至高なんだ」というロマンというか意思も一緒に伝えた。

ゲームリストはだいぶスッキリして、僕の中にだけ見えてる完成形にちょっとずつ近づいていくのが本当に楽しみ。
Detailもまだ求める至高の画面には程遠いけど、今はこれで良い。開発に必要な情報があって、ちょっと格好よくなってモチベが上がればそれで良いのだ。

それと、NOAでは「文脈」を大切にしたい。
その操作がどう影響するのかを説明しなくても感じ取れるような仕組みにしたい。
今のスクリーンショットだけ見ても伝わらないと思うけど、完成に近づくほど少しずつ伝わるんじゃないかなと思ってる。
